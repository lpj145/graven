Zero-copy & RPC & MIT

A zero-copy binary format for stored data and RPC.

Write a .graven file to define your tables and services. Generated code reads fields directly at their byte offsets without unpacking the message, using the same layout on disk and over the network.

Get started Read the docs

Format v1 specification · Borrows ideas from FlatBuffers and Cap'n Proto (history)

What you can build with Graven

Logs you read years later, fast RPC services, local caches, or binary IPC where copying and parsing cost too much.

Logs, ledgers, and archives

Every stored record has a length prefix and a CRC32C, so a crash-truncated tail reads differently from bit rot. Append data for years and read old records with new code without migrating files.

Low-latency RPC and streams

Put methods, streams, and error unions next to your data definitions. Replies add only 7 bytes of framing over TLS or a socket, and stream items arrive one frame at a time.

Caches and memory-mapped files

Fields live at fixed offsets, and strings or byte slices borrow directly from the input buffer. Reading one field from a large record skips everything else and allocates nothing.

Embedded sync and Wasm IPC

Call verify once when bytes arrive from an untrusted peer or plugin. Nesting stops at 64 levels and traversal work is bounded, so malformed input cannot blow the stack or stall a reader.

Envelopes and frames

The Entry message is the same 35 bytes on disk and on the wire. Only the wrapper changes.

Because those inner 35 bytes are identical, a server can save an incoming RPC payload into a disk envelope without re-encoding it. Frame layout

Services

Services live in the same file as your tables. A method can return a value, a typed error union, a stream, or nothing at all.

Schema

union LookupError { NotFound @1: NotFound }

#[timeout(ms = 5000)]
service Inventory {
  get  @1: (GetProduct)   -> Result<Product, LookupError>;
  list @2: (ListProducts) -> stream Product;
  ping @4: (Ping);
}

Typed client

Rust

let inv = InventoryClient::new(http_sender);
match inv.get(|w| { w.sku("cafe-500g"); }).await {
    Ok(p) => println!("{} in stock", p.view().stock()),
    Err(CallError::Err(e)) => match e.view() {
        LookupErrorVerified::NotFound(nf) => println!("missing {}", nf.sku()?),
        LookupErrorVerified::Unknown(_) => println!("lookup failed"),
    },
    Err(fault) => return Err(fault.into()),
}

JavaScript / TypeScript

const inv = new InventoryClient(async (call) =>
  (await fetch("/inventory", { method: "POST", body: call })).body!);

const r = await inv.get((w) => w.sku("cafe-500g"));
if (r.ok) show(r.value.stock());
else if (r.error.variant === "NotFound") notFound();

for await (const p of await inv.list((w) => w.limit(20)))
  add(p.name());
Typed errors
Domain errors are part of the method's return union. Transport and protocol errors stay on a separate path, so you handle them differently.
Streams
Each frame starts with its byte length, so receivers yield items as they arrive instead of buffering the whole response.
Validation codes
When a rule fails, the wire carries numeric codes for the field, rule, bounds, and reason. No prose strings over the wire, so clients format or translate messages themselves.

Protocol evolution

Every .graven file has a companion .graven.lock that you commit to git. It records the exact binary layout of every version you have shipped. When you change a definition, gravenc update checks your edit against the lock and refuses anything that would break old files or running clients. If the change is safe, it updates the lock.

Rejected

table Entry {
  account  @0: u64;
  amount   @1: i32;
  memo     @2: string?;
  currency @3: u16;
}
$ gravenc update ledger.graven
ledger.graven:5:3: field `Entry.amount` (@1): type changed
  from `i64` to `i32` (type-changed)
ledger.graven:7:3: new field `Entry.currency` (@3) is
  required: every new reader would fail on old messages;
  use `u16?` or a default (new-required)

Accepted

table Entry {
  account  @0: u64;
  amount   @1: i64;
  memo     @2: string?;
  currency @3: u16 = 986;
}
$ gravenc update ledger.graven
ledger.graven.lock: written

Quickstart

Install gravenc, create the initial .lock file, and run codegen.

1Install the compiler

cargo install graven-compiler

2Initialize the .lock file

gravenc update schemas/bank.graven --init

3Generate code, write a message, read it back

Rust

// Generate with `gravenc gen schemas/bank.graven -o src/gen` (or build.rs)
use graven::{Builder, SimplePool};
use bank::{Entry, EntryW};

let pool = SimplePool::new(4096);
let mut b = Builder::new_enveloped(&pool);
let bytes = EntryW::to_bytes(&mut b, |e| {
    e.account(1001).amount(-2500).memo("transfer");
})?;

let entry = Entry::from_bytes(&bytes)?; // checks CRC32C and runs verify
println!("{} {:?}", entry.amount(), entry.memo()?);

JavaScript / TypeScript

// Generate with `gravenc gen schemas/bank.graven -o src/gen --lang js`
import { Entry, EntryW } from "./gen/bank.js";

const bytes = EntryW.toBytes((e) =>
  e.account(1001n).amount(-2500n).memo("transfer"));

const entry = Entry.fromBytes(bytes); // checks CRC32C and runs verify
console.log(entry.amount(), entry.memo());
