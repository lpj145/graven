A binary format built for data that lasts.

Read fields straight from raw bytes with no parsing or allocation. One shared schema and lockfile keep Rust and TypeScript/JavaScript compatible across stored logs and RPC streams.

Normative format v1 spec · Inspired by FlatBuffers and Cap'n Proto (how we got here)

Built for data that outlives the code that wrote it

Write records once and keep reading them as services upgrade, storage engines change, and audits run years later.

Read in place

Fields decode directly from byte offsets. Strings and byte slices borrow straight from the buffer, so untouched fields cost zero work.

One bounded verify pass

Untrusted bytes pass through a single verify walk with fixed depth (64) and work limits, returning a trusted view without re-checking on every read.

Lockfile-guarded evolution

gravenc records every layout in a lockfile and rejects schema edits that would make old and new readers disagree.

Crash vs. corruption clarity

Normative envelope checks distinguish a write cut short by a crash from a flipped bit (CRC32C)—they are never confused.

Common fits

Ledgers & event logs Browser ↔ Rust RPC Offline & embedded sync KV storage & caches Long-term archives Wasm plugin boundaries

One message, two containers

The Entry payload is the exact same 35 bytes everywhere. Only its outer container changes between storage and network.

Zero re-encoding: a server persists what it received simply by wrapping the same payload slice in an envelope. How frames work

Services from the same schema

Declare unary methods, typed errors, and streams next to your tables. gravenc emits typed clients for Rust and browsers/Node, plus a no_std Rust server edge.

Schema

union LookupError { NotFound @1: NotFound }

#[timeout(ms = 5000)]
service Inventory {
  get  @1: (GetProduct)   -> Result<Product, LookupError>;
  list @2: (ListProducts) -> stream Product;
  ping @4: (Ping);
}

Typed client

Rust

let inv = InventoryClient::new(http_sender);
match inv.get(|w| { w.sku("cafe-500g"); }).await {
    Ok(p) => println!("{} in stock", p.view().stock()),
    Err(CallError::Err(e)) => match e.view() {
        LookupErrorVerified::NotFound(nf) => println!("missing {}", nf.sku()?),
        LookupErrorVerified::Unknown(_) => println!("lookup failed"),
    },
    Err(fault) => return Err(fault.into()),
}

JavaScript / TypeScript

const inv = new InventoryClient(async (call) =>
  (await fetch("/inventory", { method: "POST", body: call })).body!);

const r = await inv.get((w) => w.sku("cafe-500g"));
if (r.ok) show(r.value.stock());
else if (r.error.variant === "NotFound") notFound();

for await (const p of await inv.list((w) => w.limit(20)))
  add(p.name());
Errors are part of the type
Declared errors travel as typed unions checked by the compiler; transport and decode faults share one uniform handler.
Streams yield as frames arrive
Self-delimiting frames deliver each streamed item as soon as its bytes arrive, enforcing configurable size limits.
Validation speaks in codes
Broken rules return field, rule, bounds, and check reason codes—never hardcoded server text—ready for client localization.

Schema changes reviewed before they ship

Change a field type or add a required field and gravenc update refuses, citing rule and line. Add a default instead and the lockfile updates cleanly.

Rejected

table Entry {
  account  @0: u64;
  amount   @1: i32;
  memo     @2: string?;
  currency @3: u16;
}
$ gravenc update ledger.graven
ledger.graven:5:3: field `Entry.amount` (@1): type changed
  from `i64` to `i32` (type-changed)
ledger.graven:7:3: new field `Entry.currency` (@3) is
  required: every new reader would fail on old messages;
  use `u16?` or a default (new-required)

Accepted

table Entry {
  account  @0: u64;
  amount   @1: i64;
  memo     @2: string?;
  currency @3: u16 = 986;
}
$ gravenc update ledger.graven
ledger.graven.lock: written

Get started

Shared schema and lockfile on disk; native zero-copy bindings in your language.

1Install the compiler

cargo install graven-compiler

2Create your schema & lockfile

gravenc update schemas/bank.graven --init

3Generate code, write, and verify in place

Rust

// Generate with `gravenc gen schemas/bank.graven -o src/gen` (or build.rs)
use graven::{Builder, SimplePool};
use bank::{Entry, EntryW};

let pool = SimplePool::new(4096);
let mut b = Builder::new_enveloped(&pool);
let bytes = EntryW::to_bytes(&mut b, |e| {
    e.account(1001).amount(-2500).memo("transfer");
})?;

let entry = Entry::from_bytes(&bytes)?; // checks CRC32C and runs verify
println!("{} {:?}", entry.amount(), entry.memo()?);

JavaScript / TypeScript

// Generate with `gravenc gen schemas/bank.graven -o src/gen --lang js`
import { Entry, EntryW } from "./gen/bank.js";

const bytes = EntryW.toBytes((e) =>
  e.account(1001n).amount(-2500n).memo("transfer"));

const entry = Entry.fromBytes(bytes); // checks CRC32C and runs verify
console.log(entry.amount(), entry.memo());
